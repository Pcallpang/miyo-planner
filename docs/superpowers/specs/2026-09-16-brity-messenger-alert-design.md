# 메신저 알리미 (브리티 메신저 자동 정리) 설계

## 1. 개요

미요플래너의 "쪽지 붙여넣기" 기능(안내문을 붙여넣으면 Gemini가 일정을 추출해 확인 후
캘린더/To-Do/회의록에 등록) 바로 아래에, **브리티 메신저로 들어오는 쪽지를 사람이 붙여넣지
않아도 자동으로 감지해 같은 흐름에 태워주는** 신규 메뉴 "메신저 알리미"를 추가한다.

참고 프로젝트: [`created412/meum`](https://github.com/created412/meum) (MIT) — 브리티·GOE
메신저를 Windows 접근성(UI Automation)으로 읽어 할 일·마감일을 추출하는 오픈소스 프로그램.
본 설계는 meum의 **브리티 읽기 방식(접근성 API로 목록·본문을 읽는 절차, "조용할 때만
읽는다"는 운영 철학)을 참고**하되, 실제 코드는 이 저장소 안에 새로 작성한다.

## 2. 기술적 전제 (왜 설치형 프로그램이 필요한가)

브라우저에서 여는 미요플래너 웹 화면은 보안 정책상 다른 프로그램(브리티 메신저)의 창
내용을 절대 읽을 수 없다. 따라서 이 기능은 **사용자 PC에 상주하는 설치형 프로그램**이
브리티 창을 읽어 미요플래너 서버로 전달하는 구조가 필수다.

- 이 저장소(`planner`)에는 이미 `native-widget`(Electron, "미요 오늘의 시간표")이 있어
  구글 로그인·서버 통신을 검증된 방식으로 갖추고 있다.
- 그러나 이번 요청은 별도 프로젝트인 **`S04-스트레칭펫(StretchPet)`**
  (`R02-창작자/D01-앱 개발/P05-개인생활앱(Lifestyle)/S04-스트레칭펫(StretchPet)`)을
  확장해, 스트레칭 알림 캐릭터가 브리티도 함께 감시하고 말풍선으로 알려주는 방식으로
  진행하기로 사용자와 합의했다. StretchPet은 현재 순수 Electron 앱으로 서버·로그인
  기능이 전혀 없어, 이번에 처음 추가한다.
- 즉 이번 기능은 **두 개의 별도 저장소**에 걸친다: `planner`(서버 API + 웹 UI)와
  `StretchPet`(로컬 감시 + 말풍선 + 서버 전송). 이 문서는 두 저장소를 아우르는
  전체 설계이며, 구현 계획(writing-plans)은 두 저장소 각각에 대해 나눠 작성한다.

## 3. 전체 아키텍처

```
[선생님 PC]
 브리티 메신저(창)
     ↓ Windows 접근성(UI Automation)으로 읽기 — 브리티 자체는 건드리지 않음
 브리티리더 (파이썬, PyInstaller로 exe화해 StretchPet 설치 파일에 동봉)
     ↓ 새 쪽지 텍스트를 표준입출력(JSON)으로 StretchPet에 전달
 StretchPet.exe (Electron 메인 프로세스)
     ├─ 전화번호 마스킹 (010-****-**34 형태)
     ├─ 말풍선 표시: "새로운 쪽지가 있어요!" / "새로운 대화가 있어요!"
     └─ 미요플래너 계정이 연결돼 있으면 → 로그인 토큰으로 서버에 전송
              ↓ POST /api/messenger-alert/ingest
     [배포된 미요플래너 서버]
              ↓ 기존 "쪽지 → Gemini 추출" 파이프라인 재사용 (source="brity"만 추가)
              ↓ 추출 결과를 "확인 대기" 상태로 DB 저장, (계정, 메시지 해시)로 중복 방지
     [웹 화면] 사이드바 "쪽지 붙여넣기" 아래 신규 메뉴 "메신저 알리미"
              → 대기 카드 배지 표시 → 카드별 확인·수정 →
                [캘린더 등록] / [To-Do 등록] / [회의록 등록] / [무시]
```

- StretchPet은 미요플래너 계정을 연결하지 않아도 원래 기능(스트레칭 알림)과 말풍선
  알림까지는 그대로 동작한다. 계정을 연결해야만 서버 전송과 웹 화면 "메신저 알리미"
  반영이 일어난다 (StretchPet 설정의 "미요플래너 연동" 토글로 켜고 끔).
- **자동으로 캘린더/To-Do/회의록에 등록되는 일은 없다.** 항상 선생님이 웹 화면에서
  확인 카드를 직접 눌러야 반영된다 (기존 쪽지 붙여넣기와 동일한 원칙).
- 답장·전달·삭제 등 브리티를 조작하는 동작은 구현하지 않는다. 읽기만 한다.

## 4. 컴포넌트별 상세

### 4.1 브리티리더 (신규, Python, StretchPet 저장소 내 `resources/brity-reader/`)

- meum의 브리티 읽기 절차를 참고해 새로 작성:
  - `WM_GETOBJECT`로 브리티 목록 창의 접근성을 활성화해 신규 항목만 판별
  - 신규 항목이 있으면 상세 창을 열어 본문 전문을 읽고 다시 닫음
  - 클릭은 창에 마우스 메시지를 직접 전송하는 방식(커서를 움직이지 않음, meum과 동일)
- **조용할 때만 동작** (meum과 동일 철학):
  - 목록 확인 주기: 20초
  - 입력이 45초 이상 없을 때만 상세 본문을 열어봄 (근무 중 방해 방지)
  - 그래도 신호가 없으면 20분마다 한 번, 최대 2시간 밀리면 사용 중이어도 한 번은 확인
- 이미 읽은 쪽지는 로컬 상태 파일(`%LOCALAPPDATA%\StretchPet\brity-seen.json`)에
  기록해 중복 전달 방지.
- 전화번호로 보이는 패턴은 이 단계에서 바로 마스킹(`010-****-**34`)한 뒤 상위로 전달.
- PyInstaller로 단일 exe(`brity-reader.exe`)를 빌드해 StretchPet의
  `electron-builder` 설정에 `extraResources`로 포함. 사용자는 Python을 설치할
  필요가 없다.
- 브리티가 설치돼 있지 않거나 로그인돼 있지 않으면 조용히 대기(에러 팝업 없음).

### 4.2 StretchPet Electron 메인 프로세스 (확장)

- `brity-reader.exe`를 자식 프로세스로 실행해 stdout의 JSON 라인을 구독.
- 신규 항목 수신 시:
  1. 말풍선 대사 큐에 "새로운 쪽지가 있어요!" (또는 여러 건이면 "새로운 대화가
     있어요!") 추가 — 기존 `dialoguePicker` 메커니즘 재사용.
  2. 미요플래너 연동이 켜져 있으면 서버로 전송.
- **신규: 미요플래너 계정 연결** — native-widget의 `auth.js`/`pkce.js` 패턴을 그대로
  이식해 구글 로그인(PKCE, 데스크톱 클라이언트) 구현. 로그인 정보는
  `electron-store`에 암호화 없이 토큰만 저장(native-widget과 동일 수준).
- 설정 화면에 토글 추가: "미요플래너 연동" (기본값 꺼짐) — 최초 켤 때
  "브리티 쪽지 내용이 요약을 위해 외부 AI(Gemini)로 전송됩니다"라는 안내와 동의
  확인을 반드시 거친다 (동의 없이 자동 활성화 금지).
- 연동 토글을 끄면 브리티리더 프로세스 자체를 종료한다(감시 중단).

### 4.3 미요플래너 서버 (확장)

- 신규 엔드포인트 `POST /api/messenger-alert/ingest`
  - 인증: 기존 구글 로그인 토큰 검증 미들웨어 재사용.
  - 입력: `{ sender, receivedAt, body }` (이미 마스킹된 본문).
  - 처리: 기존 "쪽지 붙여넣기"가 호출하는 Gemini 추출 함수를 그대로 호출하고,
    저장 시 `source: "brity"` 필드만 추가.
  - 중복 방지: `(userId, sha256(sender + receivedAt + body))`를 유니크 키로 저장,
    이미 있으면 무시하고 200 반환.
- DB: 기존 "추출된 일정 후보" 테이블에 `source` 컬럼 추가(`paste` | `brity`,
  기본값 `paste`로 마이그레이션).
- 자동 등록 로직 없음 — 이 엔드포인트는 오직 "확인 대기" 레코드를 만들 뿐이다.

### 4.4 웹 화면 (확장)

- 사이드바 "쪽지 붙여넣기" 바로 아래 "메신저 알리미" 메뉴 신설.
- 대기 중인 카드 개수 배지 표시.
- 카드 UI: 기존 쪽지 붙여넣기 미리보기 카드를 재사용하되, 상단에 "브리티" 출처
  배지와 원문 일부(마스킹된 상태)를 함께 보여줌.
- 버튼: [캘린더 등록] / [To-Do 등록] / [회의록 등록] / [무시] — 기존 쪽지 붙여넣기와
  동일한 등록 로직 재사용.

## 5. 알림 (트레이 + 말풍선)

- StretchPet 말풍선: 새 쪽지 감지 즉시 표시(요청사항).
- 추가로 StretchPet 트레이 아이콘에 "확인 대기 N건" 배지 표시(브레인스토밍 단계 결정
  사항) — 웹 화면을 열어보지 않아도 밀린 건수를 알 수 있게 함.

## 6. 데이터 흐름 요약

1. 브리티 새 쪽지 도착
2. 브리티리더가 조용한 시점에 본문 읽고 전화번호 마스킹
3. StretchPet이 말풍선 표시 + (연동 시) 서버로 전송
4. 서버가 Gemini로 추출 → 확인 대기 카드 저장 (중복이면 무시)
5. 선생님이 웹 화면 "메신저 알리미"에서 확인 → 등록 버튼 클릭 시에만 캘린더/To-Do/회의록 반영

## 7. 에러·예외 처리

| 상황 | 처리 |
|---|---|
| 브리티 미설치/미로그인 | 브리티리더가 조용히 대기, 에러 팝업 없음 |
| 미요플래너 서버 응답 실패(네트워크 등) | 로컬에 재시도 큐 보관 후 다음 주기에 재전송, 최대 7일 지난 항목은 폐기(무한 누적 방지) |
| Gemini 추출 실패/애매한 결과 | 기존 쪽지 붙여넣기와 동일하게 "날짜·시간 확인 필요" 배지로 표시 |
| 동일 쪽지 중복 수신 | 서버에서 해시 기준으로 무시 |
| 사용자가 미요플래너 연동을 끔 | 브리티리더 프로세스 종료, 이후 감시 없음 |

## 8. 개인정보·보안

- 전화번호는 브리티리더 단계에서 마스킹 후 전송.
- 쪽지 본문은 (연동 켠 경우에 한해) 요약을 위해 Gemini API로 전송됨 — 최초 연동 시
  고지·동의 필수.
- 로컬 상태 파일(마지막으로 본 쪽지 기록)은 컴퓨터 밖으로 나가지 않음.
- 답장·전달·삭제 기능 없음(읽기 전용).

## 9. 범위 밖 (Out of scope, 이번 단계)

- GOE 메신저 지원 (요청 범위는 브리티만).
- meum 자체와의 직접 연동/설치 의존 (meum 설치 여부와 무관하게 독립 동작).
- 확인 없는 자동 등록.
- 모바일 앱 지원.

## 10. 구현 계획 분리

- `planner` 저장소: 서버 API(`/api/messenger-alert/ingest`) + DB 마이그레이션 +
  웹 화면 "메신저 알리미" 메뉴/카드 UI.
- `StretchPet` 저장소: 브리티리더(Python) + Electron 통합 + 미요플래너 로그인 연동 +
  말풍선/트레이 알림.
- 각 저장소에서 이 문서를 참조하는 별도의 구현 계획(plan)을 writing-plans 스킬로
  작성한다.
