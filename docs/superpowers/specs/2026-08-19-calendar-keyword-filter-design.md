# 대시보드 캘린더 키워드 필터 — 설계

작성일: 2026-08-19

## 문제

대시보드 캘린더에 구글 일정이 전부 표시된다. 특정 종류의 일정만 보고 싶을 때
(예: '상담'이 들어간 일정만) 눈으로 골라내는 수밖에 없다.

## 요구사항

캘린더 헤더의 `학사일정 겹쳐보기` 옆에 키워드를 입력할 수 있게 하고,
입력된 키워드가 제목에 들어간 구글 일정만 캘린더에 보이게 한다.

## 범위

**거른다**
- 월간 캘린더 격자의 구글 일정
- 날짜 클릭 팝업(`DateActionModal`)의 구글 일정 목록

**거르지 않는다**
- 학사일정 — 이미 `showSchoolSchedule` 토글로 끄고 켤 수 있어 역할이 겹친다
- 휴일 — 날짜 배경 성격
- 할 일·회의록 — 구글 일정이 아니다
- 주간 요약, 매트릭스 등 대시보드 캘린더 밖의 화면

대시보드 캘린더 섹션은 `hidden lg:block`이므로 이 기능은 자동으로 데스크톱 전용이다.
모바일 레이아웃은 건드리지 않는다.

## 동작

**매칭** — 일정 **제목**에 키워드가 포함되면 통과. 대소문자와 앞뒤 공백은 무시한다.
키워드가 여러 개면 **하나라도** 맞으면 통과(OR). 캘린더에 보이는 것이 제목이므로
제목만 본다 — 설명이나 장소로 걸리면 왜 걸렸는지 화면에서 알 수 없다.

**빈 키워드** — 키워드가 하나도 없으면 필터가 켜져 있어도 전부 표시한다.

**유지** — 키워드 목록은 `Settings.eventKeywords`로 서버에 저장해 기기가 바뀌어도 남는다.
필터 On/Off는 저장하지 않고 **기본 꺼짐**이다. 접속하자마자 일정이 사라져 있어
당황하는 상황을 막는다.

## 구조

**`client/src/lib/events.ts`** — 순수 함수 하나를 추가한다.

```ts
filterEventsByKeywords(events: GEvent[], keywords: string[]): GEvent[]
```

기존 `eventsOnDay`와 같은 자리이고, `events.test.ts`가 이미 있어 테스트를 바로 붙인다.
필터링 로직이 순수 함수 하나에 모여 있어 캘린더와 팝업이 어긋날 수 없다.

**`client/src/types.ts`** — `Settings`에 `eventKeywords: string[]` 추가.
**`client/src/lib/storage.ts`** — 기본값 `[]`.

**`client/src/views/DashboardView.tsx`** — 걸러진 배열을 한 번 만들어
`MonthCalendar`의 `events`와 `DateActionModal`의 `eventsOnDay(...)`에 똑같이 넘긴다.

`MonthCalendar`와 `DateActionModal`은 수정하지 않는다. 이미 받은 `events`를 그리는
컴포넌트이므로, 걸러진 배열을 주면 그대로 동작한다.

## UI

캘린더 헤더의 `학사일정 겹쳐보기` **왼쪽**에 `키워드` 토글 버튼을 둔다.
키워드가 있으면 버튼에 개수 뱃지를 붙인다.

토글을 켜면 헤더 아래로 칩 줄이 펼쳐진다.
- 입력 후 Enter로 칩 추가, 칩의 X로 개별 삭제
- 중복·빈 문자열은 추가하지 않는다
- 필터로 숨겨진 일정이 있으면 `n개 숨김`을 함께 표시한다

숨김 개수 표시가 안전장치다. 키워드를 걸어둔 걸 잊고 "일정이 왜 없지"라고
헤매는 것을 막는다.

## 테스트

`client/src/lib/events.test.ts`에 `filterEventsByKeywords` 테스트를 추가한다.

- 키워드가 비면 전부 통과
- 제목에 키워드가 포함된 일정만 통과
- 키워드 여러 개면 OR로 동작
- 대소문자 무시
- 키워드 앞뒤 공백 무시
- 제목에 없고 설명에만 있으면 통과하지 않음
