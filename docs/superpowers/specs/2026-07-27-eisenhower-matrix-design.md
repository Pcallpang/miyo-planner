# 우선순위 매트릭스(아이젠하워) 설계

작성일: 2026-07-27

## 목적

할 일이 몰릴 때 "급해 보이지만 중요하지 않은 일"을 걸러내기 위해, 할 일을
중요도 × 긴급도 2×2 매트릭스에 배치해서 보고 정리할 수 있게 한다.

**회의록(`Meeting`)에는 적용하지 않는다.** 회의는 이미 날짜·시간이 정해진
일정이라 사용자가 순서를 조정할 수 없고, 아이젠하워는 순서를 조정할 수 있는
일에 쓰는 도구이기 때문이다.

## 데이터 모델

`Todo`에 선택 필드 두 개를 추가한다. 둘 다 optional이므로 기존 저장 데이터를
변환할 필요가 없다.

```ts
interface Todo {
  // ...기존 필드
  important?: boolean;      // 없으면 '중요하지 않음'
  urgentOverride?: boolean; // 없으면 마감일 기준 자동 판정
}
```

`Settings`에 `urgentDays: number`(기본 3)를 추가한다. 기존 사용자 데이터는
`normalizeSettings`가 기본값을 채운다.

## 긴급도 판정 — `client/src/lib/eisenhower.ts`

순수 함수로 분리해 단위 테스트한다.

```ts
isUrgent(todo, urgentDays, today): boolean
```

1. `urgentOverride`가 `undefined`가 아니면 그 값을 그대로 반환한다.
2. `dueDate`가 없으면 `false`.
3. 마감일까지 남은 일수가 `urgentDays` 미만이면 `true`.
   기본값 3이면 오늘·내일·모레가 긴급.
4. **마감일이 지난 항목은 항상 긴급**이다. 지난 일이 조용히 아래 칸으로
   내려가면 안 된다.

```ts
quadrantOf(important, urgent): QuadrantId
```

| | 긴급함 | 긴급하지 않음 |
|---|---|---|
| **중요함** | `do` — 지금 급해요! | `plan` — 미리 챙겨둬요 |
| **중요하지 않음** | `quick` — 후딱 해치워요 | `later` — 천천히 해도 돼요 |

## 매트릭스 화면

사이드바 '나의 하루'에 **우선순위 매트릭스**(`ViewId: 'matrix'`)를 대시보드
바로 아래에 추가한다.

2×2 그리드로 분면을 배치하고, 각 항목은 대시보드 To-Do 카드와 같은 수준으로
조작한다 — 완료 체크, 수정, 삭제, 메모 펼치기.

완료된 할 일은 기본 숨김이며 토글로 볼 수 있다.

## 드래그 앤 드롭

외부 라이브러리 없이 브라우저 기본 HTML5 드래그 API를 쓴다(번들 크기 유지).

- **세로 이동** → `important` 변경
- **가로 이동** → `urgentOverride`를 목적지 분면의 긴급값으로 고정
- **대각선** → 둘 다 변경
- 드롭 결과가 자동 판정값과 일치하면 `urgentOverride`를 **저장하지 않는다.**
  불필요한 고정이 쌓이는 것을 막는다.

### 고정 해제

두 가지 경로를 제공한다.

1. 고정된 항목에 📌 배지가 붙고, 클릭하면 자동 판정으로 되돌아간다.
2. 마감일을 수정하면 고정이 자동 해제된다. 날짜를 바꿨는데 옛 고정이 남으면
   혼란스럽기 때문이다.

### 접근성

드래그만으로는 키보드·터치 사용자가 조작할 수 없다. 각 항목에 **중요도 토글
별 버튼**을 함께 두어 드래그 없이도 세로축을 바꿀 수 있게 한다.

## 나머지 화면 변경

- **TodoModal**: "중요함" 토글 추가. 긴급도는 자동이므로 *"마감일 기준 자동
  판정 · 매트릭스에서 변경 가능"* 안내만 표시한다. 여기서 긴급도까지 물으면
  할 일 추가할 때마다 선택지가 늘어 입력 마찰이 생긴다.
- **대시보드 TodoCard**: 중요 항목 앞에 작은 별 표시. 정렬은 바꾸지 않는다.
- **SettingsView**: "긴급 기준 일수" 숫자 입력.
- **MeetingModal / MeetingsCard**: 변경 없음.

## 테스트

`client/src/lib/eisenhower.test.ts` (vitest, 기존 테스트와 동일 방식)

- 마감일 없음 → 안 긴급
- 오늘 마감 / 경계값(`urgentDays` 당일과 그 다음날) → 긴급 여부
- 마감일이 지난 항목 → 항상 긴급
- `urgentOverride`가 자동 판정보다 우선
- 드롭 시 자동 판정과 일치하면 override를 제거하는 로직

## 하지 않는 것

- 회의록에 중요/긴급 적용
- 분면별 정렬 규칙, 분류(업무/교과/개인) 필터 — 필요해지면 그때 추가한다
- 드래그로 마감일을 실제로 변경하는 동작 — 실수로 끌었을 때 학교 제출
  마감일이 사라질 수 있어 위험하다
