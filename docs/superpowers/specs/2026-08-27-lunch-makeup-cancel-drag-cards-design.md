# 오늘의 시간표 — 점심시간·보강·휴강 드래그 카드 설계

## 배경

지금 "오늘의 시간표"(`WeeklyGrid.tsx`)에서 보강·휴강은 칸을 클릭해 여는
`TimetableCellModal`에서만 다룰 수 있고, 점심시간은 그냥 시간표 칸에 "점심시간"이라는
과목명을 직접 입력하는 방식(`lib/nonClassSubjects.ts`)뿐이다 — 모든 요일에서 같은
교시 위치에만 넣을 수 있다.

사용자 요청:

1. 시간표 아래에 "점심시간 / 보강 / 휴강" 카드 3개를 두고, 드래그로 적용
2. 보강·휴강 카드는 특정 (요일, 교시) 한 칸에만 적용(그 칸이 비어있든 채워져
   있든 상관없이 덮어씌움)
3. 점심시간 카드는 요일별로 다른 위치에 넣을 수 있어야 하고, 그 요일 뒤 교시들이
   화면상 한 줄 밀려나야 함(교시 번호나 실제 수업-교시 연결은 안 바뀜, 시각적 표시만)

같은 날 아침에 시도했다가 되돌린 "요일별 교시 시간표"(`aa41909` → revert `ed088e3`)는
`settings.periodTimes` 자체를 요일마다 다르게 만드는 더 무거운 접근이었다. 이번 설계는
그 문제를 데이터 구조 변경 없이, 화면 표시 전용으로 훨씬 가볍게 해결한다.

## 데이터 모델

### 새 필드: `lunchAfterPeriod`

```ts
// types.ts
/** 요일(1=월~5=금)별로 점심시간 표시줄을 몇 교시 뒤에 끼워 넣을지. 값이 없는
 *  요일은 점심줄이 없다. 순수 화면 표시용 — 교시 번호·시간표 데이터·진도 계산에는
 *  전혀 영향을 주지 않는다. */
export type LunchAfterPeriod = Record<number, number>; // day -> 0-based period index
```

`AppData`(`storage.ts`의 저장 대상)에 `lunchAfterPeriod: LunchAfterPeriod` 필드를
추가하고, 기존 `canceledLessons`/`makeupLessons`/`swapOverrides`와 같은 레벨에 둔다.
없는 요일 키는 점심줄 없음으로 취급(기본값 `{}`).

### 보강·휴강: 변경 없음

`canceledLessons`(`{date, period}`)와 `makeupLessons`(`{date, period, subject, room}`)를
그대로 재사용한다. 드래그는 **새로운 입력 경로**일 뿐이고, 저장되는 데이터 구조나
기존 클릭→모달 흐름은 그대로 남는다.

## 화면 구조 변경

### 표 → 요일별 독립 열(column) 구조

지금 `WeeklyGrid.tsx`는 `<table>`로 "행 = 교시, 각 행 안에 5개 요일 칸"이다. 이
구조에서는 한 요일만 밀어낼 수 없으므로(모든 요일이 같은 `<tr>`을 공유), 표를
CSS grid 기반으로 다시 짠다:

```
[교시 번호 세로 목록]  [월요일 칸들(세로로 쌓임)]  [화요일 칸들]  [수요일 칸들]  [목요일 칸들]  [금요일 칸들]
```

- 왼쪽 "교시" 열은 지금처럼 1~`periodCount`가 세로로 나열된 참조용 라벨일 뿐이다.
  점심줄이 없는 요일과는 높이가 맞지만, 점심줄이 낀 요일은 그 지점부터 왼쪽 라벨과
  높이가 어긋난다 — 이건 사용자가 원하는 "그 요일만 밀림" 동작의 당연한 결과이므로
  의도된 것으로 둔다.
- 각 요일 열은 `flex flex-col`로 자기 교시 칸(`1교시, 2교시, …, periodCount교시`)을
  순서대로 쌓되, `lunchAfterPeriod[day]`가 있으면 그 인덱스 칸 바로 다음에 "점심시간"
  표시줄(작은 높이의 회色/민트색 바)을 끼워 넣는다.
- 교시 번호(`i + 1교시`)와 실제 수업 데이터 연결(`slotAt`, `swapOverrides` 등)은
  지금처럼 `(day, period index)` 그대로 유지 — 점심줄은 그 사이에 얹히는 시각 요소일
  뿐, 배열 인덱스를 밀지 않는다.

### 카드 트레이

`WeeklyGrid.tsx`의 표 아래, 흰 박스 안 맨 밑에 가로로 카드 3개를 추가한다:

```tsx
<div className="mt-3 flex gap-2 border-t border-slate-100 pt-3">
  <DragCard label="점심시간" kind="lunch" />
  <DragCard label="보강" kind="makeup" />
  <DragCard label="휴강" kind="cancel" />
</div>
```

각 카드는 `draggable`이며 드래그 시작 시 컴포넌트 state에 어떤 종류(`kind`)의
카드를 드래그 중인지 기록한다(`draggingCard: 'lunch' | 'makeup' | 'cancel' | null`).
기존 "칸 자체를 옮기는" 드래그(`dragging: Cell | null`, 교환용)와는 완전히 별도
state로 관리해 서로 섞이지 않게 한다.

## 드래그 동작

### 점심시간 카드

- **넣기**: 카드를 특정 요일 열의 "교시 N과 N+1 사이 틈"에 드롭하면
  `lunchAfterPeriod[day] = N`(0-based)으로 저장한다. 그 틈 자리에는 평소엔 보이지
  않는 얇은 드롭 존이 있고, 카드를 끌고 오면 그 틈이 강조 표시된다.
- **이미 그 요일에 점심줄이 있는 경우**: 새로 드롭한 위치로 덮어써 옮긴다(요일당
  최대 1개).
- **빼기**: 이미 끼워진 점심시간 줄을 다시 카드 트레이 쪽으로 드래그하면
  `lunchAfterPeriod`에서 그 요일 키를 삭제한다.
- 다른 요일에는 전혀 영향이 없다.

### 보강 카드

- 카드를 특정 (요일, 교시) 칸에 드롭하면, 그 칸이 비어있든 채워져 있든 상관없이
  칸 근처에 작은 입력창(과목·교실 두 입력, 기존 `TimetableCellModal`의 보강 입력
  부분과 동일한 필드)이 뜬다.
- 저장하면 기존 `saveMakeup(dateKey, period, subject, room)`을 그대로 호출한다.
  결과적으로 클릭 → 모달 → 보강 입력과 완전히 같은 데이터가 남고, 진입 경로만 하나
  늘어난 것이다.
- 입력창을 취소하면 아무 것도 저장하지 않는다.

### 휴강 카드

- 휴강은 켜고 끄는 것뿐이라 입력할 내용이 없다. 카드를 (요일, 교시) 칸에 드롭하는
  즉시 그 칸을 휴강 처리한다(입력창 없음) — 기존 `toggleCanceled(dateKey, period,
  subject, className)`을 그 칸의 현재 표시 내용(`slotAt` 기준)으로 바로 호출한다.
- 이미 휴강인 칸에 다시 드롭하면 `toggleCanceled`가 그대로 다시 토글되어 휴강이
  풀린다(기존 로직 그대로).

### 기존 기능과의 공존

- 칸을 클릭해 `TimetableCellModal`을 여는 기존 방식은 그대로 남는다. 카드 드래그는
  같은 결과(보강 저장, 휴강 토글)에 도달하는 **추가 진입로**다.
- 칸끼리 자리를 바꾸는 기존 드래그(칸 버튼 자체를 끌어 `SwapConfirmModal` 띄우는
  흐름, `dragging` state)와 카드 드래그(`draggingCard` state)는 서로 다른 상태로
  분리되어 있어 다른 드롭 핸들러 분기를 탄다 — 드롭 시점에 `draggingCard`가 있으면
  카드 동작을, 없으면 기존 칸 교환 동작을 수행한다.
- 점심시간 줄은 순수 표시 전용이라 `slotAt`, `subjectProgress`, 차시 계획표
  계산에는 전혀 관여하지 않는다.

## 검증

- 개발 서버에서 직접 확인:
  - 점심시간 카드를 수요일 3교시 뒤에 드롭 → 수요일만 그 지점부터 한 줄씩 밀리고
    월·화·목·금은 그대로인지
  - 같은 카드를 화요일 1교시 뒤에도 드롭 → 화요일도 독립적으로 밀리는지
  - 점심줄을 카드 트레이로 다시 드래그 → 사라지고 그 요일이 원래대로 돌아오는지
  - 보강 카드를 빈 칸/채워진 칸 각각에 드롭 → 입력창이 뜨고 저장 후 칸에 "보강 ·
    과목" 배지가 뜨는지 (클릭으로 넣은 보강과 동일하게 보이는지)
  - 휴강 카드를 드롭 → 입력창 없이 즉시 휴강 배지가 뜨는지, 다시 드롭하면 풀리는지
  - 기존 칸 교환 드래그(손잡이)가 카드 드래그와 안 섞이는지
- `npx tsc --noEmit` 통과 확인. 별도 자동 테스트는 없음(이 프로젝트 관례).
